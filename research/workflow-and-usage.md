# 组合与使用流程

本指南给出一个可复核的 Codex 工作方式：先选一个主 Skill 管理案件，再按任务加入一到两个补充检查。这样材料和版本有明确归属，审查结论也能逐项比较。

## 先按输入选主 Skill

| 你的主要输入或目标 | 主 Skill 建议 | 补充 Skill |
|---|---|---|
| 论文、学位论文、公开预印本 | Paper2Patent | Evidence-First 用于证据定位；CN Patent Drafting 用于复核草稿结构 |
| 代码、设计文档、实验记录和研发材料 | CN Patent Drafting | Evidence-First 负责证据清点；Patent Skills 可作为阶段清单 |
| 材料多、含未公开技术或多个团队来源 | Evidence-First 先盘点和设披露边界，再选一个撰写 Skill | Paper2Patent 仅适合论文型输入；CN Patent Drafting 适合工程材料 |
| 想看覆盖更广的模块化项目 | 中国专利.skill 可作为试用对象 | 先确认 Codex 技能发现、依赖、文件输出和检索功能 |
| 想试整合式桌面代理 | Sati 独立评估 | 不要把桌面应用当作可直接安装的单个 Skill |

选择逻辑：

1. **论文转专利**：Paper2Patent 的来源约束、绘图、格式检查和 Codex 实测说明更直接。
2. **一般研发材料转申请**：CN Patent Drafting 明确面向 Codex，材料类型和交付目标较广。
3. **证据或保密风险高**：先用 Evidence-First 把材料、来源、事实状态和外部检索权限管好，再做实质撰写。
4. **模块多、星数高**：中国专利.skill 值得做兼容性试用，但要把“星数高”与“Codex 已验证”分开。
5. **全流程或 OA 等后续业务**：先确认工具确有适用数据源、流程入口和更新机制；不要只看项目名称或功能宣传。

## 从技术想法到申请后的阶段地图

| 阶段 | Codex 应完成的工作 | 参考项目 | 必须保留的人工确认 |
|---|---|---|---|
| 0. 建案和保密 | 建立案件目录、确认用户目标、发明类型、材料范围、是否允许联网 | Evidence-First | 哪些材料可上传、可检索或可披露 |
| 1. 材料盘点 | 列出每份文件、版本、来源位置、缺失内容；保留原始文件 | Evidence-First、CN Patent Drafting | 是否已收齐且可用于撰写 |
| 2. 技术理解 | 解释技术问题、必要技术特征、技术效果和可选实施方式 | CN Patent Drafting、Patent Skills | 技术方案表述是否符合发明人实际方案 |
| 3. 公开与时间线 | 记录论文、产品、演示、代码、会议等的公开状态和日期 | Paper2Patent | 公开是否影响申请策略，需代理师判断 |
| 4. 现有技术检索 | 形成中英文检索词、分类号线索、检索记录和候选对比文件 | Patent Skills、中国专利.skill、Sati | 检索范围、数据库和结果是否足以支持判断 |
| 5. 发明点与可专利性分析 | 对候选点去重，比较最接近现有技术，记录差异特征与风险 | Paper2Patent、CN Patent Drafting | 是否继续、拆分申请或改变保护策略 |
| 6. 权利要求规划 | 先做权利要求树，逐项标明依据、必要性、备选限定和缺口 | Paper2Patent、CN Patent Drafting | 独立权利要求边界和申请布局 |
| 7. 申请文本和附图 | 草拟权利要求、说明书、摘要、图纸计划与附图标记 | Paper2Patent、CN Patent Drafting、中国专利.skill | 每项技术事实和图示是否真实、充分 |
| 8. 质量审查 | 查术语一致、引用关系、权利要求支持、实施例充分、数字和图号；记录问题 | Evidence-First、Paper2Patent | 关闭重大问题，确认可以交代理师 |
| 9. 代理师和申请人审核 | 提交可审阅草稿、证据索引、缺口表和检索说明 | 任一主 Skill | 代理师审核法律问题，申请人确认发明和权属信息 |
| 10. 正式申请 | 核对请求书信息、附件、申请人/发明人、优先权和提交渠道 | 以国家知识产权局最新要求为准 | 由申请人或专利代理师正式确认并提交 |
| 11. 审查与后续 | 归档通知书和期限；逐点分析审查意见、证据、修改基础与答复策略 | 中国专利.skill、Sati；其他项目仅作参考 | 代理师审核答复和修改，按官方通知期限办理 |

本仓库收集的项目主要辅助第 0 至第 9 阶段。它们不会因为生成一套文件就自动完成官方申请、缴费、案件监控或取得授权。正式办理应以国家知识产权局的最新法律、指南、通知和系统要求为准。

官方入口：

- [中国国家知识产权局专利业务办理系统](https://cponline.cnipa.gov.cn/)
- [国家知识产权局官网](https://www.cnipa.gov.cn/)

## 推荐的 Codex 运行方式

### 第一步：新建案件工作目录

把案件材料放到独立目录，原始文件单独保留。避免把不同申请人的文件混进一个工作目录。未确认外部检索许可前，先设为仅本地处理。

建议先要求 Codex 输出：

- 案件目标和申请类型；
- 输入文件清单；
- 每个关键技术事实及其文件、页码、段落或图号；
- 缺失信息和需要发明人回答的问题；
- 是否会调用网络、浏览器或外部服务；
- 预计输出文件及保存路径。

### 第二步：确认公开和检索边界

在搜索前，让 Codex 说明准备使用哪些关键词、会发送哪些内容。对尚未公开的技术资料，不要把完整说明、代码或客户信息直接提交给第三方网站或外部模型。先使用脱敏的功能词、技术问题和公开资料检索；必要时由发明人或代理师审核检索式。

### 第三步：完成检索并保留检索账本

检索账本至少记录：

- 数据库或搜索引擎名称；
- 检索日期、检索式、分类号和语言；
- 候选文件的公开号、公开日、申请人、专利族信息；
- 对应段落或附图位置；
- 哪些特征相同、哪些特征不同；
- 由于覆盖范围或访问限制仍未解决的缺口。

网页搜索结果摘要不能代替对专利公开文本的阅读。涉及法律结论时回到官方法律法规和审查指南的适用版本。

### 第四步：先确认权利要求树，再生成长文

在写完整说明书前先审阅权利要求计划。至少检查：

- 独立权利要求是否只包含解决技术问题所必需的技术特征；
- 每个从属权利要求是否加入一个清楚的备选限定；
- 每项限定是否在技术材料或实施例中有依据；
- 是否把实验目标、推断或尚未实现的设计写成已取得的效果；
- 方法、装置、设备、存储介质等类别是否由实际技术方案支持。

### 第五步：分开生成与审查

主 Skill 负责生成并保存正式草稿。补充 Skill 收到一份只读草稿和明确任务，例如：

> 请只做权利要求支持性审查。逐项列出权利要求限定、说明书依据位置、问题类型和建议问题；不要改写或覆盖原稿。无法找到依据的项目标记为待人工确认。

另一类独立审查提示：

> 请检查说明书是否支持权利要求中的术语、范围、参数和每个可选实施方式。引用原文段落或图号；不要补造实施例，也不要直接修改文件。

使用补充 Skill 后，先比较审查意见、定位分歧，再由主 Skill 在新版本中修改。不要让多个 Skill 并行写入同一个权利要求文件。

### 第六步：交付前建立审阅包

建议交付目录包含：

- 申请文件草稿；
- 技术交底书或发明点说明；
- 现有技术检索记录与代表性对比文件；
- 权利要求逐项依据表；
- 待补信息和未解决风险；
- 附图源文件和预览；
- 自动检查结果；
- 文件版本号、生成日期和修改记录。

在正式发送前，检查文件正文、批注、修订痕迹、隐藏内容、元数据和文件名中是否包含不该披露的信息。

## 可复制的 Codex 总提示词

下面的提示词可作为案件起始指令。将其中的 Skill 名称和材料路径换成你选定的项目：

> 使用 `<主 Skill 名称>` 处理当前专利案件。先说明你读取了哪些材料和规则文件，再按阶段推进。  
>   
> 先盘点文件、建立技术事实到来源位置的对应表，并区分实测事实、材料记载、推断和拟议设计。遇到来源不足的内容，列为待补，不要自行补造。  
>   
> 在任何外部检索前，先列出准备发送的脱敏检索词和会访问的外部服务，等待我确认。检索时记录数据库、日期、检索式、文献号、公开日和相关位置。  
>   
> 先向我提交候选发明点、最接近现有技术对照、风险和权利要求树；我确认后再写申请文本。  
>   
> 生成草稿后做权利要求支持性、术语一致性、实施例充分性、摘要和附图编号检查。保存新版本，不覆盖原始材料或我确认过的版本。  
>   
> 交付草稿、依据索引、待补问题、检索账本、附图和检查结果，并标明需要专利代理师审核的事项。不得声称已正式提交或保证授权。

## 让多个 Skill 协作时的规则

- 一个案件只指定一个 Skill 作为主流程和版本负责人。
- 其他 Skill 收到只读输入，执行一个明确检查任务。
- 不让不同 Skill 同时改同一份权利要求、说明书或附图。
- 每个关键结论都带来源位置；每个未解决分歧都进入问题清单。
- 让 Skill 报告其用到的法律文件版本、数据库、网页和日期。
- 不把星数、自动检查通过或模型信心当作法律结论。
