# 材料、保密与证据

本文件用于任何新案或新一轮申请文件工作。先看材料里实际有什么，再决定是否搜索、起草或要求补充。

## 案件信息

尽可能记录；未知项保留为待确认，不推定：

- 案件标识、创建日期、工作语言、联系人占位符
- 技术主题、预期专利类型：发明、实用新型、外观设计，或待判断
- 发明人/设计人、申请人、职务发明或合作研发背景、权属待核实项
- 希望保护的技术、核心产品/方法、拟申请国家或地区
- 首次公开、销售、展览、论文/预印本、公开演示、先前申请和优先权日期
- 现有交底、论文、源代码、设计稿、CAD、试验记录、会议纪要、样机照片
- 用户要求的交付物、已知通知书和官方截止日期

不得替用户作发明人认定、权属结论或优先权资格判断。必要时把问题交给企业知识产权负责人或专利代理师。

## 先检查保密边界

1. 标记未公开、受合同限制、个人敏感、客户信息和第三方资料。
2. 先在本地阅读并提炼通用技术词；不要把原始文档、源码、样机图、客户名或完整技术方案提交给外部搜索。
3. 若要联网检索，使用经用户允许的泛化关键词；写明哪些信息被用于查询。
4. 未经许可不公开、不提交仓库、不发送给第三方、不把材料写入 Git 提交。
5. 发现误提交的秘密或个人信息时停止继续传播，告知用户并协助确定安全处置。

## 证据台账

对每份来源给稳定 ID，例如 SRC-001；对每个技术事实/限定给 E-001。记录：

| 字段 | 内容 |
|---|---|
| ID | 稳定来源或证据编号 |
| 文件与位置 | 相对路径、页码、章节、图号、代码符号或时间戳 |
| 原始内容 | 简短准确摘录或可定位摘要；保留原件，不改写事实 |
| 状态 | documented、measured、inferred、designed、unknown |
| 适用范围 | 哪个候选发明点、步骤、特征或效果 |
| 外部性 | 是否含第三方内容、公开来源、许可或隐私限制 |
| 后续动作 | 可直接使用、需发明人确认、需试验验证、不得公开 |

状态含义：

- **documented**：材料中明确记载，但不必然代表已实施或测试。
- **measured**：有可追溯的测试条件、样本、数据和记录。
- **inferred**：根据资料作出的技术解释，不得写成用户确认的事实。
- **designed**：拟议方案或未来设计，不得伪装为已有实现。
- **unknown**：无证据；通过问题清单向用户补充。

## 候选发明点

每个候选点分别记录：

- 要解决的具体技术问题
- 区别于常规技术的技术手段及必要关系
- 预期/已验证的技术效果及支撑证据
- 实现材料是否足以让本领域技术人员实施
- 可能的专利类型和保护主题
- 与同项目其他候选点的重叠、可分性及风险

在用户选定方案前，不将所有候选内容混成一个申请。缺技术事实就提出精确问题，不用模型自行补造。
