# 1. 收集材料并建立证据台账

先弄清楚案件事实，再决定是否检索或起草。未知信息要标为“待确认”，不要猜。

## 收集哪些信息

- 专利类型：发明、实用新型、外观设计，或待判断
- 技术方案、应用场景和要解决的问题
- 发明人/设计人、申请人和可能的权属关系
- 论文、预印本、网页、展览、销售、演示或先前申请的时间
- 交底书、代码、图纸、CAD、测试记录、会议纪要和样机照片
- 目标国家/地区、需要的交付物、已知通知和截止日期

不要代替用户认定发明人、权属、优先权资格或法律上的公开时间。

## 先检查保密要求

1. 标记未公开技术、个人信息、客户资料和受合同限制的文件。
2. 先在本地整理材料，不要把原始文件或完整技术方案发给外部网站。
3. 如需联网查新，先确认用户允许使用外部检索。
4. 使用不暴露机密的关键词，并记录用了哪些词。
5. 不要把案件材料或个人信息提交到这个 GitHub skill 仓库。

## 给材料编号

给每个文件一个来源编号，例如 SRC-001。记录文件路径、版本、日期和具体位置。给每项技术事实一个证据编号，例如 E-001，并记录它支持哪个技术特征。

状态只使用以下五类：

| 状态 | 含义 |
|---|---|
| 已记载 | 文件中有明确说明，但不一定经过实施或测试 |
| 已测量 | 有可追溯的测试数据和条件 |
| 推断 | 根据材料作出的解释，尚未由用户确认 |
| 设想 | 计划或建议中的方案，尚未实现 |
| 待确认 | 当前没有足够信息 |

证据台账可从 templates/evidence-ledger.csv 开始。

## 挖掘候选专利点

每个候选点单独说明：

- 要解决的技术问题
- 关键技术手段及部件/步骤关系
- 能达到的效果及其证据
- 哪些内容已实现，哪些仍是设想
- 可能适用的专利类型
- 与其他候选点是否重叠

先让用户选定方向，再对该方向做完整检索和起草。证据不足时列出具体问题，不要自行补全。
