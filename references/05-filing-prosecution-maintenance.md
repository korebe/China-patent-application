# 提交、审查与授权后维护

本文件支持案卷管理和专业人员准备。它不代替国家知识产权局系统、官方通知或代理师判断。

## 提交前

1. 阅读 references/06-authoritative-sources.md，确认当前提交渠道、申请表式和电子系统公告。
2. 核对申请类型、申请人、发明人/设计人、发明名称、优先权/分案关系、附图和申请文件清单。
3. 生成待办清单，明确哪些资料仍待申请人确认，哪些由代理师处理。
4. 请申请人/代理师确认最终文本、请求书信息、公开时点和正式提交策略。
5. 由有权申请人或代理机构在官方专利业务办理系统完成身份认证、签名、递交和缴费。保留系统回执、提交文件版本、日期时间、申请号和缴费凭证。

不得用草稿文件名或本地保存时间推定申请日。申请日和后续事件以官方回执、通知和现行规则核准。

## 案卷台账

每一案件维护可续办的台账，包含：

- 案件标识、申请类型、申请人/代理人、申请号及官方页面
- 实际提交版本及哈希/归档位置、递交回执、申请日、优先权日
- 每份官方通知的全文、送达渠道、收到日期、系统记录的期限和责任人
- 费用类别、官方金额来源、应缴日、缴费凭证和减缴状态
- 当前阶段、下一事项、负责人、复核人、状态和最近更新时间
- 本地输出的期限计算说明、起算事件、规则来源、核算人和复核状态

对每项期限至少记录：期限事项、触发事件、官方记载的日期、法定/指定期限来源、计算规则、预估到期日、官方界面显示、责任人和复核状态。任何不确定项标为“待核实”，并尽早提醒用户联系代理师或官方客服。不要只存一个计算出的日期。

## 收到审查意见或补正通知

先收齐并读取：通知书、当前有效申请文件、此前答复/修改、引证文件、官方送达记录。逐项拆解通知内容：

| 项目 | 记录 |
|---|---|
| 官方指出的问题 | 引用通知原文及页码/段落 |
| 所依据规则 | 现行官方法条/指南段落 |
| 影响的权利要求/说明书/附图 | 精确到特征与位置 |
| 对比文件教导 | 原文证据和页码/权项 |
| 事实/法律分析 | 分别记录，不混写 |
| 答复选项 | 解释、修改、补正、程序咨询或专业升级 |
| 修改依据 | 原始提交文件中的支持位置 |
| 申请人决定 | 采纳/不采纳及确认日期 |

答复的建议步骤：

1. 区分形式缺陷、清楚/支持/充分公开、客体、新颖性/创造性、单一性、优先权及其他理由。
2. 对每条审查意见做问题—规则—事实—结论分析；对比文件逐特征核验，不依赖摘要。
3. 比较答复策略：解释现有权利要求、限缩/修改、删除权项、补充形式资料或寻求代理师意见。评估保护范围损失和后续影响。
4. 修改仅限当前程序允许范围并基于原始披露；标出逐处差异和支持位置，禁止加入新技术事实。
5. 形成意见陈述草稿、修改后的权利要求/说明书、修改对照表、证据/法条清单和待确认问题。
6. 由申请人/专利代理师确认最终策略和文本，之后在官方系统递交并保存回执。

不得承诺授权，不得把预测当作审查员真实意见。收到驳回决定时，先核实救济路径与期限，再由专业人员决定复审/诉讼。

## 授权登记及授权后

以官方授权通知、登记手续通知和专利业务办理系统中的案卷信息核对登记期限、应缴费用和证书下载。只有系统或官方规则核实后才记录完成状态。

授权后维护至少包括：

- 专利号、授权日、权利人、权利要求最终文本和证书归档
- 年费年度、官方缴费窗口、应缴金额/减缴状态、缴费凭证
- 权利转让、许可、质押、著录事项变更等可能影响的手续
- 保护期、年费提醒、年费未缴/恢复风险及责任人
- 需要时的专利权评价、无效风险或侵权/FTO专业审查

年费金额、减缴规则、期限和滞纳处理必须从当前官方系统或现行规则核对，不在此固定数字。不要在本 skill 中保存账户密码、验证码、签章文件或支付凭证副本以外的支付认证信息。

## 结案

记录最后状态和证据：递交/答复回执、官方决定、授权证书、费用凭证、剩余待办和责任人。把暂时无法解决的事项显式留在台账中，不以“已完成”掩盖未决官方手续。
